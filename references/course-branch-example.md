# 课程分支示例：课件不是 notebook 导出时怎么办

主流程假设课件是 **渲染出来的 notebook 导出**（有 `In [n]:` / `Out[n]:` 边界，直接照抄单元格序列）。
有些课不是这样——典型的是大数据 / 分布式实验课，课件是"步骤 + 终端截图"。这类差异**写成一份分支文档**，
不要改动主流程。本文既是操作指引，也是"该怎么给一门新课写分支文档"的模板。

## 1. 先判断课件形态

| 课件长什么样 | 单元格序列怎么来 |
| --- | --- |
| `In [n]:` / `Out[n]:` 交替 | 逐个 `In` 一个 CODE，`Out` 是自检基准 |
| 步骤 + 终端/控制台截图 | 每张截图里的**命令**提成一个 CODE；banner 与 WARN 日志丢掉，只留真实结果 |
| 纯文字步骤 + 代码块 | 每个代码块一个 CODE，步骤说明压成 MD |
| 图片型讲义（无文字层） | 只能逐页看渲染图；`pypdf.extract_text()` 返回空串就是这种 |

## 2. 环境差异要显式写进 notebook

课件常写着几年前的环境（老发行版、老 API、Python 2）。本机是新版时**老 API 要按新版改写**，
并在 notebook 开头加一节"环境说明"写清课件环境与本机环境、改了哪些调用。
不写这一节，答辩/评审时第一个被问的就是"为什么课件写 X 你跑 Y"。

## 3. 执行参数

- 首次启动要拉起 JVM 这类重量级运行时的，`--timeout` 给到 900 以上，别用默认 600。
- 依赖 `JAVA_HOME` / `HADOOP_HOME` 之类的环境变量：这属于机器环境，**不要塞进本技能档案**，
  出 `Unsupported class file major version` 这类错就按 ask-user-checklist 问用户本机怎么配的。
- 内网数据源（课程服务器、校园网地址）在校外不可达：先问，同意后才就地取材派生，并在报告里注明。

## 4. 交付形态可能根本不是 ipynb

有的课要的是 **md 报告 + 本人终端截图**，目的是证明结果自己跑过、不被判抄课件图。
那种交付不要用本技能，改用终端截图类技能。纯 ipynb + PDF 交付时不需要截图——
notebook 的执行输出本身就是证据，前提是**真的执行过**，`audit` 必须看到非空输出。

## 5. 命名规则可能有两类

| 任务 | 命名 |
| --- | --- |
| 实验报告（要交上去的流水） | 档案的 `deliver_pattern`，默认 `{id}-{name}-{exp}` |
| 章节知识点总结（自己复习用） | 按内容命名，不带署名，例如 `第5章-DataFrame与SparkSQL.ipynb` |

第二类不是交付物：`deliver --dest <目录>` 显式指定目录，或干脆 `os.replace` 自己搬。

## 6. 给一门新课写分支文档的骨架

```
## 课件形态：…（截图/文字/图片型讲义）→ 单元格怎么提
## 环境差异：课件环境 vs 本机环境，改了哪些 API，超时给多少
## 课件与数据：读档案哪几个字段，数据找不到时问谁
## 命名与交付：文件名规则、要不要截图、交几个文件
```

具体路径一律写"读档案 `courses.<k>.*`"，不要在这份文档里写绝对路径——那是档案的活。
